# Лабораторная №6. Каталог электроприборов

React + TypeScript + React-Bootstrap; Redux Toolkit и thunk для домена приборов; Axios-клиент, сгенерированный по OpenAPI NestJS. Аутентификация — ручной Axios и обычный dispatch, без thunk и вызовов сгенерированных методов пользователей. TypeORM и Redis-сессии существующего бэкенда сохранены.

## Запуск

### 1. Инфраструктура

Запустить Docker Desktop. В Settings → Resources → WSL Integration включить интеграцию с используемой Ubuntu, если команда `docker` в WSL не найдена.

В терминале WSL:

```bash
docker start nest_postgres nest_adminer minio_storage
sudo service redis-server start
```

Эти команды запускают существующие сервисы с прежними данными. Если Redis уже работает в контейнере `nest_redis`, вместо команды службы использовать `docker start nest_redis`; одновременно два Redis на 6379 запускать не нужно.

Если на порту 5432 вместо контейнера работает системный PostgreSQL и появляется знакомая ошибка пароля:

```bash
sudo service postgresql stop
docker restart nest_postgres
```

### 2. Бэкенд — первый терминал

```bash
cd '/home/artorias/IU5/Web-frontend/energy-calculator-react lab6'
npm ci
npm run start:dev
```

`npm ci` нужен при первоначальной установке зависимостей; при последующих запусках достаточно `npm run start:dev`. Используется существующий корневой `.env`. Новая БД и миграции для ЛР6 не нужны. Сервер — http://localhost:3000, Swagger — http://localhost:3000/api, OpenAPI — http://localhost:3000/api-json.

Ошибка EADDRINUSE означает, что 3000 уже занят: остановить старый сервер через Ctrl+C или использовать уже работающий экземпляр. Не запускать несколько копий бэкенда.

### 3. Фронтенд — второй терминал

```bash
cd '/home/artorias/IU5/Web-frontend/energy-calculator-react lab6/frontend'
npm ci
npm run dev
```

Открыть **http://localhost:5173**. Использовать `localhost` последовательно для Swagger и фронтенда: cookie для `127.0.0.1` и `localhost` различаются.

Vite читает параметры из `frontend/.env`, если он создан по `.env.example`. По умолчанию:

- `/api` → `http://127.0.0.1:3000`, путь сохраняется;
- `/s3` → `http://127.0.0.1:9000`, префикс `/s3` удаляется;
- адреса `http://localhost:9000/appliances/<имя>` преобразуются фронтендом в `/s3/appliances/<имя>`;
- при другом адресе MinIO указать `S3_TARGET` и `VITE_S3_ORIGIN` в `frontend/.env`, затем перезапустить Vite.

`npm run preview` служит для просмотра сборки, а показ лабораторной с проксированием выполняется через `npm run dev`.

### Только гостевые mock без бэкенда

Остановить NestJS через Ctrl+C, оставить Vite работающим. Открыть `/appliances-catalog` или `/appliances-feed`. После неудачного запроса появляется предупреждение и резервные карточки. Инфраструктуру для этого показа запускать не требуется. Ошибка соединения в Network ожидаема: это демонстрация переключения на mock.

При восстановлении бэкенда нажать «Обновить список» или перейти на страницу заново. Ошибки предметной области 400/401/403/404 и JSON-ошибка приложения 500 не заменяются mock-успехом. При потере связи у вошедшего пользователя UI переключается в гостя.

## Страницы и работа пользователя

| Адрес | Содержимое и действия |
| --- | --- |
| `/appliances-catalog` | Карточки в два столбца, изображение, название, мощность, температура, число лайков. Ползунок мощности и «ОК» отправляют `minPower` на сервер. «Обновить список» повторно получает данные. «Удалить» доступно только после входа и при `isOwner=1`. |
| `/appliances-feed` | Первый опубликованный прибор. Видео, описание «Ещё/Меньше», мощность, температура, число лайков. «Далее» использует API `next=true`; после последнего сервер возвращает первый. |
| `/appliances-feed/:id` | Выбранный опубликованный прибор. Кнопка сердца ставит/снимает лайк только после входа и при данных API. |
| `/appliances-draft` | Защищённая страница добавления. При отсутствии черновика: название и обязательные файлы, затем «Далее». После создания/при существующем черновике: описание, мощность и температура, затем «Опубликовать». Название и сохранённые медиа на втором шаге только для просмотра. |
| `/login` | Электронная почта и пароль существующего пользователя, «Войти», ошибки ввода/запроса. |

В меню четыре пункта: лента, добавление, плитка, вход/выход. Гость может просматривать приборы и открыть вход; добавление заблокировано. Регистрация выполняется существующим `POST /api/users/register` в Swagger/Postman, отдельная страница регистрации этой лабораторной не требуется.

На первом шаге **POST `/api/appliances`** передаёт только `applianceName`, файлы `image` и `video`; создаёт/обновляет черновик. Затем GET черновика получает полные поля. На втором шаге **PUT `/api/appliances/draft`** передаёт только `description`, `powerWatts`, `minTemperature`. Успех открывает опубликованный прибор в ленте. Файлы выбираются из `frontend/public/media/default.png` и `default.mp4` либо свои подходящего формата, до 50 МиБ каждый.

Для лайка используется POST `/api/appliances/:id/like`, `{ "value": 1 }` или `0`. Для удаления — DELETE `/api/appliances/:id`; это soft delete на сервере. После успешного изменения Redux сразу обновляет интерфейс.

Все операции показывают блокирующую анимацию и блокируют повторные нажатия. Ошибки отображаются пользователю. Для отсутствующих и недоступных медиа применяются локальные `default.png`, `default.mp4`.

## Redux и сессия после F5

`src/store/authSlice.ts`:

- `user`, `isAuthenticated`, `loading`, `error`;
- обычные actions `authStarted`, `loggedIn`, `loggedOut`, `authFailed`.

`src/store/appliancesSlice.ts`:

- `minPower`, `items`, `feed`, `draft`;
- `catalogSource`, `feedSource`: API или mock;
- `error`, `requests`: активные запросы и индикатор;
- `listRequest`, `feedRequest`: защита от устаревших ответов;
- `fetchAppliances`, `fetchApplianceFeed`, `fetchApplianceDraft`, `createAppliance`, `publishAppliance`, `deleteAppliance`, `setApplianceLike` — thunk по теме приборов.

`configureStore` подключает thunk middleware и Redux DevTools. Собственный Context и RTK Query не используются. `Provider` — стандартный компонент React Redux.

Redux хранится **только в памяти**, без localStorage/persist. После F5 интерфейс становится гостевым, фильтр сбрасывается в 0; cookie `sessionId` остаётся до истечения срока/выхода. Автоматического входа по cookie при старте нет. На сервере сессия всё ещё действительна, поэтому ответ публичного GET с cookie может содержать `isOwner=1`: пользовательские кнопки дополнительно проверяют `isAuthenticated` из Redux и остаются скрыты.

HttpOnly-cookie отправляется браузером автоматически; фронтенд не читает `document.cookie`. После повторного входа UI снова пользовательский. Выход вызывает сервер, удаляет cookie/Redis-сессию и сбрасывает фильтр и данные пользователя. При ошибке связи во время выхода сообщение показывается пользователю, успешный выход не имитируется.

## Кодогенерация

Сгенерированный файл `src/api/generated/Api.ts` не редактируется вручную. Понятные имена методов заданы `operationId` в `src/appliance/appliance-api.controller.ts` бэкенда.

При работающем сервере:

```bash
cd '/home/artorias/IU5/Web-frontend/energy-calculator-react lab6/frontend'
OPENAPI_URL=http://localhost:3000/api-json npm run generate-api
```

Без работающей инфраструктуры можно экспортировать контракт из тех же реальных декораторов, не подключая БД, Redis и MinIO:

```bash
cd '/home/artorias/IU5/Web-frontend/energy-calculator-react lab6'
node scripts/export-openapi.cjs
cd frontend
npm run generate-api
```

В репозитории уже есть снимок `frontend/openapi.json` и результат генерации. Для обычного запуска генерацию повторять не нужно. Доменные thunk вызывают именно методы `applianceApi.api.*` из сгенерированного класса. Методы пользователей могут присутствовать в клиенте как часть общей схемы, но вход/выход вызывают только ручной `authApi` в `src/api/index.ts`.

## Проверка вручную

1. Без NestJS показать каталог (6 mock-карточек), фильтр 2000 Вт (2 карточки), 3000 Вт (пусто), ленту и резервные медиа `/appliances-feed/24`.
2. Запустить инфраструктуру и NestJS. В каталоге нажать «Обновить список»: предупреждение исчезает, видны данные БД, в Network — GET `/api/appliances?minPower=...`.
3. Зарегистрировать тестового пользователя через Swagger, если его ещё нет. Войти **через фронтенд** с его email/паролем: меню показывает «Выход» и добавление.
4. Создать и опубликовать тестовый прибор. Проверить его в ленте и каталоге, поставить и снять лайк, проверить количество. У чужих карточек кнопки удаления нет.
5. Открыть черновик повторно до публикации: сервер возвращает заполненные данные. Отсутствие черновика (`404`) означает начальный шаг, это штатная ситуация.
6. Изменить свой тестовый прибор в Adminer, обновить список: значения во фронтенде должны совпасть с БД.
7. После входа нажать F5: меню показывает «Вход», Redux `auth.isAuthenticated=false`, cookie всё ещё есть в Application.
8. Повторно войти, установить фильтр, выйти: фильтр 0, cookie удалена, добавление недоступно.
9. Удалить собственный тестовый прибор: он исчезает; запись в БД сохраняется со статусом `deleted`.

Для этого снимка использовать созданный прибор с реальными файлами, не default. |

Для снимка 7: в Adminer выбрать PostgreSQL, сервер `postgres`, базу `appliances_db`, учётные данные существующего стенда. Узнать ID собственного тестового прибора в API и заменить `123` ниже. Сначала SELECT, затем UPDATE и повторный SELECT:

```sql
SELECT appliance_id, appliance_name, power_watts, creator_id, publication_status
FROM appliances WHERE appliance_id = 123;

UPDATE appliances
SET appliance_name = 'Чайник после изменения в БД', power_watts = 2300
WHERE appliance_id = 123 AND publication_status = 'published';

SELECT appliance_id, appliance_name, power_watts, creator_id, publication_status
FROM appliances WHERE appliance_id = 123;
```

**Не копировать число 123 без замены:** изменять только собственную созданную карточку. Удаление для проверки выполнить после отчётных снимков.

Для снимка 10 можно импортировать `postman/lab6.postman_collection.json` из корня проекта. У коллекции переменные `baseUrl=http://localhost:3000`, `sessionId=<Value из браузера>`. Регистрация и вход в Postman для этого кадра не нужны: используется браузерная сессия. После F5 она сохраняется, после нового входа старое значение может перестать действовать — копировать заново.

## Автоматические проверки

```bash
npm run build
npx playwright install chromium
sudo npx playwright install-deps chromium
npm run test:browser
```

Браузерные проверки запускают собственный **изолированный HTTP-стенд** на 3036/3037 и Vite на 5173. Перед ними остановить обычный Vite через Ctrl+C. Тесты используют реальные запросы Axios через оба Vite-прокси, но тестовые данные и cookie отдельные; рабочие PostgreSQL, Redis и MinIO не используются.
```bash
docker stop nest_postgres nest_adminer minio_storage
sudo service redis-server stop
```
