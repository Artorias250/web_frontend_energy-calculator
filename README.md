# Каталог электроприборов — фронтенд

Веб-приложение для просмотра электроприборов и их характеристик: мощности и минимальной температуры эксплуатации. Фронтенд разработан на React и TypeScript с использованием React-Bootstrap, React Router, Redux Toolkit и Axios.

Приложение содержит четыре страницы: ленту, каталог, добавление прибора и вход. Нижняя навигационная панель отображается на всех страницах и содержит пункты «Лента», «Добавление», «Плитка», «Вход» или «Выход». Гостю доступны просмотр приборов, фильтрация и страница входа. Создатель после авторизации может добавлять и публиковать приборы, удалять собственные карточки, ставить и снимать лайки.

## 1. Лента приборов

**Адреса:** `/appliances-feed` и `/appliances-feed/:id`.

Страница отображает одну опубликованную карточку прибора. При открытии без ID сервер возвращает первый опубликованный прибор. Адрес с ID позволяет перейти к определённой карточке, например из каталога.

На странице отображаются:

- короткое видео, которое автоматически воспроизводится без звука и повторяется;
- название и описание прибора;
- мощность в ваттах и минимальная температура эксплуатации в градусах Цельсия;
- количество лайков и кнопка с изображением сердца.

Кнопка «Ещё» раскрывает описание, «Меньше» сворачивает его. Кнопка «Далее» запрашивает следующую опубликованную карточку через API с параметром `next=true`; после последней карточки сервер возвращает первую. Создатель может нажать на сердце, чтобы поставить или снять лайк. Для гостя изменение лайков недоступно.

При отсутствии или ошибке загрузки видео используется локальное видео по умолчанию. Если резервное видео также недоступно, отображается изображение прибора или изображение по умолчанию. При недоступном бэкенде лента получает данные из резервной mock-коллекции и работает только в гостевом режиме.

## 2. Каталог приборов

**Адрес:** `/appliances-catalog`.

Страница отображает опубликованные приборы в виде карточек, расположенных в два столбца. Каждая карточка содержит изображение, название, мощность, минимальную температуру эксплуатации и количество лайков. Нажатие на карточку открывает соответствующий прибор в ленте.

В верхней части страницы расположен фильтр минимальной мощности: ползунок от 0 до 3000 Вт с шагом 50 Вт, текущее выбранное значение и кнопка «ОК». После нажатия «ОК» применённое значение сохраняется в Redux и передаётся бэкенду в параметре `minPower`. Фильтрация данных API выполняется на сервере. Значение фильтра сохраняется при переходах между страницами в рамках работы приложения.

Кнопка «Обновить список» повторно загружает каталог с применённым фильтром. Если подходящих приборов нет, отображается сообщение с предложением уменьшить минимальную мощность.

После авторизации у собственных карточек с признаком `isOwner = 1` появляется кнопка «Удалить». Она выполняет логическое удаление на сервере: прибор исчезает из каталога, но запись сохраняется в БД со статусом `deleted`. У чужих карточек и в гостевом интерфейсе кнопка не отображается.

При отсутствии или ошибке загрузки изображения показывается локальное изображение по умолчанию. При недоступном бэкенде каталог отображает mock-коллекцию с предупреждением и локальной фильтрацией по мощности; пользовательские действия недоступны.

## 3. Добавление прибора

**Адрес:** `/appliances-draft`.

Страница доступна только создателю после входа. При прямом переходе гостя приложение перенаправляет его на страницу авторизации. При открытии запрашивается существующий черновик текущего пользователя; если его нет, отображается начальная форма создания.

Создание и публикация выполняются в два этапа.

**Первый этап — создание черновика:**

- поле «Название устройства»;
- выбор файла фотографии и её предпросмотр;
- выбор файла видеозаписи и её предпросмотр;
- кнопка «Далее».

Название, изображение и видео обязательны. Нажатие «Далее» отправляет `POST /api/appliances` в формате `multipart/form-data` только с полями `applianceName`, `image` и `video`. Сервер сохраняет файлы в MinIO и создаёт черновик. После этого фронтенд получает полные данные черновика и открывает второй этап.

**Второй этап — публикация:**

- сохранённые название, фотография и видео отображаются для просмотра;
- поле «Описание»;
- поле «Мощность (Вт)» — целое неотрицательное число;
- поле «Мин. температура (°C)» — целое число;
- кнопка «Опубликовать».

Все три поля публикации обязательны. Кнопка «Опубликовать» отправляет `PUT /api/appliances/draft` с полями `description`, `powerWatts` и `minTemperature`. После успешной публикации приложение открывает прибор в ленте. Если у создателя уже есть черновик, страница сразу отображает второй этап с его данными.

## 4. Вход

**Адрес:** `/login`.

Страница предназначена для аутентификации существующего пользователя и содержит:

- поле «Электронная почта»;
- поле «Пароль» со скрытым вводом;
- кнопку «Войти»;
- сообщение об ошибке при неверных данных или неудачном запросе.

После отправки формы выполняется ручной запрос Axios `POST /api/users/login`. При успешном ответе браузер сохраняет HttpOnly-cookie `sessionId`, а фронтенд обычным действием Redux записывает пользователя и признак авторизации. Запрос входа не использует thunk и сгенерированный API-клиент. Пользователь перенаправляется в каталог, пункт «Вход» меняется на «Выход», становятся доступны добавление приборов и пользовательские действия.

Нажатие «Выход» выполняет ручной запрос Axios `POST /api/users/logout`. После успешного ответа удаляется серверная сессия и cookie, очищается пользовательское состояние Redux, фильтр мощности сбрасывается в 0 и открывается каталог.

Состояние Redux хранится только в памяти. После обновления страницы через F5 интерфейс становится гостевым, хотя cookie сессии может оставаться в браузере. Автоматического восстановления пользовательского интерфейса по cookie нет; для него нужно повторно выполнить вход. Отдельная страница регистрации не предусмотрена: регистрация доступна через существующий API бэкенда.
